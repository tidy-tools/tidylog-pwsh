# Contributing to TidyLog
Thanks for looking. This project doesn't follow the usual open-source contribution pattern.

## The short version
TidyLog is a curated single-maintainer project. Contributions are discouraged in favour of feedback via email.
TidyLog is small, opinionated, and shaped by a specific design ethos. Its value comes from consistency and restraint, not from breadth of features. On a project this small, it's easier to maintain with one person making decisions than with a community consensus, so the project is deliberately structured that way.

## In practical terms...
**Bug reports** are welcome via GitHub Issues. Please use the bug-report template so I have the version, OS, terminal, and repro steps I need. Issues are reviewed periodically, typically every few weeks. There's no response SLA as this is a personal project, not a supported product.  

**Feature ideas** are welcome by email, at feedback@tidylog.dev. I promise to read and consider every one. TidyLog's design ethos is "less is more, only when less is genuinely enough" and during design every element in the library earned its place through careful consideration. New features adhere to this same approach. This means that pull requests are not accepted for features. _If you have an idea please email first_.

Security issues: see SECURITY.md.

## Forks are welcome
If TidyLog isn't what you want it to be, and you have a clear vision for what it should become, please fork it. MIT license permits it, and I actively encourage it. The one request is that substantially different projects use a substantially different name, so users don't confuse the two.

## Why it's structured this way
Community-driven open source works well for projects where the design surface is broad and contributions genuinely improve the whole. It works less well for projects where the design surface is narrow and every addition risks diluting the coherence. TidyLog is deliberately in the second category.  

If you find that stance frustrating, that's fair. If you find it clarifying, welcome. Feedback by email is genuinely valued, even (especially) the critical kind.
